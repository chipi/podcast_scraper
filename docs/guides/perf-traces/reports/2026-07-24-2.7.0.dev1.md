## Common-sense assessment — what's off vs where we'd want to be

**Two ~5–6 s cold experiences stick out; everything warm is snappy (<800 ms, most <30 ms).**

> **Decision (2026-07-24):** both cold-starts below are **accepted for 2.7.0.dev1** —
> a conscious trade-off this release, not an unaddressed regression. Recorded here
> so the next reader knows they were seen and deferred, not missed. Re-evaluate if
> a future capture shows the cold path worsening.

1. **Search cold-start first query — 5.8 s.** (Accepted this release.) The first `/api/search`
   after the api boots pays LanceDB index-open + embedding-model load + first
   hybrid search; warm is 784 ms. A user who lands and searches immediately eats
   the full 5.8 s. Want: < ~2 s. **Fix direction:** warm the index + embedding
   model at api startup (or on corpus-path set), so the first *user* query is
   never the cold one. Highest-value, self-contained.

2. **Graph time-to-canvas — ~5.8 s (from the [graph-v3 report](graph-v3-tuning-2026-07-19.md), not re-captured this run).**
   The sibling cold experience, client-side (fcose + KG-second-wave full rebuild).
   Want: < ~2 s. Known; the real fix is the incremental-append refactor
   (`cy.add(delta)` instead of destroy+rebuild) deferred to #1219.

3. **Warm results-paint — 784 ms.** Acceptable for a 99-episode two-tier hybrid
   search, but on the high side; a < 500 ms target is reasonable later. Secondary
   to the cold-start fix (which dwarfs it).

4. **operator-compare — 796 ms (steady).** Two subject-scoped searches + two
   `build_briefing_pack` passes, run serially. Tolerable for an explicit heavy
   action; if it grows, parallelize the two sides (they're independent). Low
   priority.

5. **Everything else is where we'd want it** — filter-apply 15 ms, cmdk-open
   3 ms, operator-cluster 15 ms, all three surfaces 14–27 ms. No action.

**Bottom line:** the app is snappy once warm; the whole perf story is **two
cold-start paths (search ~5.8 s, graph ~5.8 s)**. Search cold-start is the
cheapest big win (preload/warmup); graph cold-start is a known deferred refactor.
