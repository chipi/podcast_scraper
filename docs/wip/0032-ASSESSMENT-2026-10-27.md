# 0032 (`naming_voices_rederived`, held under #2380): still needed? (2026-10-27)

Asked by prod for the operator (open-items item 17): after 0031 and 0033-0036, is 0032 still
needed, or should it be retired? The operator decides; this is the evidence.

0032 never ran on prod and is not registered. Its list (`NAMING_VOICES`, 166 voices in 126
episodes) was read once on 2026-10-17 against the naming code of sha-ded80e0, before the reviewed
verdict protocol (basis column, deciding segment, line hash, list sha256) that 0034-0037 use.

## What its 166 voices are now

Read-only, scratch `rm27/m32_assess.py` and `m32_overlap.py`, on snapshot-prod-20261025 (before
0034-0036 were applied on prod):

- **All 166 are still in the state 0032 was written for** (`still_old_would_apply` 166). Nothing
  before 0034 touched them.
- **By kind:** 48 add a name, 30 rename, 88 take a name off.
- **75 of them are also in 0034's list**, which prod applied on 2026-10-27 with a fresh reviewer's
  verdicts:

| 0032 wants | 0034's review | Voices | What running 0032 now would do |
|---|---|---|---|
| name off | `WRONG_PERSON` (0034 took it off) | 7 | nothing: already done |
| name off | `CORRECT` (0034 kept it) | 67 | **remove 67 names a later, stricter review confirmed** |
| rename | `CORRECT` (0034 kept the old name) | 1 | contradict that review |

- **91 voices have no later coverage:** 48 additions, 29 renames, 14 unnamings. They were read

  (the talk floor, the voice identity rung, and today's third-person veto on the forced host seat).

## Assessment

- **As written, 0032 cannot run.** 67 of its entries contradict 0034's shipped verdicts; applying
  them would make served naming worse, which the deploy rule forbids. Because the entry rule
  refuses only when a voice moved on, it would not catch these: the 67 voices still carry the names
  0032 expects.
- **Its purpose is partly served.** 7 unnamings were done by 0034.
- **What could still be worth having:** the 91 uncovered voices, and among them the **29 renames**
  most of all, since a rename can be a wrong-person fix (rank 1).

## Options for the operator

1. **Retire 0032** (recommended). Remove the module, its tests and its held record, or mark the
   record `retired` with this file as the reason. If the 91 voices are wanted, they are
   re-derived as a new reviewed list (0037's machinery: frozen list, blind reads with basis and
   deciding segment, verdicts bound to the list) through their own record. That is a new work item,
   not part of the current validation pass.
2. **Retire 0032 and drop the 91.** Accept them as they are.
3. **Trim 0032 to the 91 and run it.** Not recommended: one 2026-10-17 read, no basis protocol, and
   code that has moved.
