### B. #1191 plumbing — the deep, risky part (schema fields exist; population does not)
The `rank`/`tier`/`routing_tag`/`salience` fields are in the schema (optional, so artifacts still
validate without them). Populating them + removing truncation is intricate:
- **Preserve the tier**: `gi/value_gate.py::value_gate_keep_mask` computes a per-insight tier then
  discards it (returns only a keep-mask). Expose it (a `value_gate_tiers` or extend the return) and
  thread it to the insight-node builder.
- **De-truncate**: remove the pipeline-side `insight_texts[:max_insights]` slice in
  `gi/pipeline._resolve_insight_specs` (~1439) and the `build_artifact` prefilled cap; KEEP the
  per-provider `min(…, ceiling)` extraction budget (ADR: safety only). **Risk**: more insights →
  more grounding calls → watch the LLM call-fuse (ADR "fuse coupling").
- **routing_tag / rank / salience**: deterministic from existing signals (tier × speaker-role ×
  grounding rollup); corpus-novelty (embeddings, `about_edges.py` scaffold) is a rank-quality
  refinement that can come with the deferred rubric work.
- **Quote-alignment correctness**: the value gate's keep-mask must stay index-aligned with quotes
  (see the big warning in `value_gate.py`) — the reason to do this unhurried.
